1. 企业级 AI 落地四大命门与挑战
Part I: 痛点与挑战
1. 严重幻觉陷阱

脱离真实数据的纯 Prompt 提示词极易引发指标伪造与数字幻觉，在金融、医疗、法律领域造成致命合规风险。

2. Token 爆炸与高延迟

缺乏场景路由，将用户所有持仓股票全量塞入 Prompt 动辄消耗 30k+ Token，导致响应延迟高达 12 秒且成本飙升。

3. 多租户数据泄漏风险

若缺乏数据库物理规则约束与敏感凭证脱敏，用户的持仓、交易记录、Webhook 密钥易发生跨租户越权泄露。

4. 外部噪音与虚假传闻

未经清洗将社交平台（Reddit/X）谣言与官方定量指标混杂，严重损害投研严谨性并导致错误交易指令。

2. 场景驱动的大模型分工与定向路由策略
Part II: 模型分工与路由
Gemini 2.5 Flash

多轮对话、ADK 工具调用与定向上下文路由

  • 定向路由：自动识别用户询问标的（如 NVDA），精准剪枝其余 18 只股票，Token 消耗骤降 >80%（2.8万 ➔ 2500 Token），延迟降至 1.8 秒。
  • 应用场景：实时 AI 选股问答、盘前执行简报、盘后复盘快讯。
Gemini 2.5 Flash-Lite

高并发量化风险拟合

  • 优势：成本骤降 70%，极高并发吞吐耐受度，适于批量高频计算。
  • 应用场景：组合压力测试、板块暴露计算、定时任务缓存预热。
Gemini 2.5 Pro

机构级深度定性推演

  • 优势：超长上下文与多因子因果推理能力，支持解构多财季财报与电话会。
  • 应用场景：宏观催化动因归因、美联储决议深度研报、估值建模。

5. 多租户分级权限 (RBAC) 与数据隐私安全隔离
Part IV: 权限与隐私安全
🛡️ Firestore 规则层物理隔离 (firestore.rules)
  • 数据库物理防护：部署规则强制限制 request.auth.uid == userId，客户端 SDK 只能读写自己的文档。
  • 杜绝前端传参 UID：后台所有操作严格从 Google 签名的 Firebase ID Token 中解密身份，杜绝越权扫描。
  • 共享数据只读防护：公共股票池与宏观缓存仅允许已认证用户只读，写入仅限云端 Admin SDK。
🔑 敏感 Webhook 令牌单向脱敏
  • 动态脱敏显示：企业微信（key=36a2****6987）与 Discord（.../f0C3****q6tk）密钥返回前端时自动打码。
  • 非破坏性保存：用户提交包含 **** 的表单时，后台智能保留原真实私钥，防止密钥丢失或被截获。
  • 多等级权益配额：Free (1持仓)、Trial (5持仓, 2观察)、Paid/Pro (15持仓, 15天宽限期)、Super/Admin (无限制)。

7. 七重自主自愈 SRE 闭环矩阵 (MAPE-K)
Part V: 自愈闭环架构
🤖 1. 结构自审与反思闭环

Pydantic 拦截大模型输出，校验失败自动组装 Reflection Error Prompt 二次反思推理（最多重试 3 次）。

⚡ 2. 状态机熔断降级闭环

FMP 出现故障时熔断器跳闸（CLOSED ➔ OPEN），无缝平滑回退至 yfinance 历史镜像与缓存。

🔍 3. 缓存缺失自填补闭环

Cloud Scheduler 定时扫描 Firestore 缺失缓存，在每周研报推送前自动触发预热任务（Prewarm）。

📊 4. 策略胜率演化闭环

扫描过去 30 天选股信号与 T+5 真实走势，实时计算盈亏比并标注 OPTIMAL / CRITICAL 评级。

🚨 5. 异常告警反馈闭环

FastAPI 全局拦截异常直连 GCP Error Reporting，并在 Discord/企微自动发送带代码修复建议的告警。

🛡️ 6. 失控字符清洗与限频闭环

自动清洗 Markdown 表格分隔符失控死循环，限制单次推送上限 5 个 Chunk 并加入 0.35 秒延迟规避微信频控拦截。
